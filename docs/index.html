Build an agent that reads a synthetic workshop brief and drafts a social post. Then add the controls that make that draft safe to release: input screening, a tool allowlist, sensitive-data redaction, a human approval boundary, traces, and a repeatable evaluation gate. Finish by removing an irrelevant archive from the model context and comparing the two runs.

You will use Google ADK 2.11.0 in two modes.

The fixture is not an AI model. It is not evidence of model quality, token savings, or live response speed. It keeps the workshop reproducible when credentials or the network fail. Publishing is always simulated. Nothing is sent to LinkedIn.

Core lab: about 100–120 minutes. Optional Cloud extensions: 45–60 minutes, excluding project access setup.

Ask two questions throughout: what may this agent do, and what evidence shows it does the job well?

What you'll learn

  • Where a control has to run, and why an instruction cannot replace it
  • How to block a hostile prompt and a hostile tool result
  • How to redact an email before it reaches the model
  • How to deny a tool the agent was not allowed to call
  • How to bind human approval to the exact text, destination, and lifetime
  • How to shrink context without dropping the facts the draft needs
  • How to gate a local release on six explicit checks

class FixtureLlm(BaseLlm):
    """Scripted test double. It does not understand arbitrary prompts."""

    model: str = "fixture-llm"

    @property
    def capabilities(self) -> LlmCapabilities:
        return LlmCapabilities(output_schema_and_tools=False)

    async def generate_content_async(self, llm_request, stream=False):
        _active["model_calls"] = _active.get("model_calls", 0) + 1
        if _active["model_calls"] > 4:
            yield _text("Stopped because the model-call limit was reached.")
            return
        responses = _function_responses(llm_request)
        if not responses:
            yield _function_call("get_brief")
            return
        yield _text(_draft_from_tool(responses[-1]))

lab/policy.py

MARKERS = (
    "ignore all previous instructions",
    "bypass approval",
    "reveal the api key",
)


def screen(text: str) -> str:
    if text is None:
        return "allow"
    if any(marker in text.lower() for marker in MARKERS):
        return "block"
    return "allow"

Replace the body of before_model_callback. Returning a response skips the model call.

async def before_model_callback(self, *, callback_context, llm_request):
    user_text = _user_text(llm_request)
    if user_text and screen(user_text) == "block":
        _active["blocked"] = True
        _active["trace"].append("input_blocked")
        return _text("This request was blocked by the input screen.")
    _active["trace"].append("model_request")
    return None

import re

_EMAIL = re.compile(r"[A-Za-z0-9._%+\-]+@[A-Za-z0-9.\-]+\.[A-Za-z]{2,}")


def redact(text: str) -> str:
    return _EMAIL.sub("[EMAIL_REDACTED]", text)

Approval is a SHA-256 fingerprint of the destination plus the exact text, an expiry, and an atomic publish transaction.

lab/review.py

def fingerprint(text: str, destination: str) -> str:
    payload = f"{destination}\n{text}".encode()
    return hashlib.sha256(payload).hexdigest()

ALLOWED_DESTINATIONS = frozenset({"workshop-channel"})

publish checks, in this order, inside BEGIN IMMEDIATE:

  1. Destination not allowed: BLOCKED destination_not_allowed
  2. Already published: ALREADY_PUBLISHED
  3. Rejected, or fingerprint does not match the current text and destination: BLOCKED approval_required
  4. Missing or elapsed expiry: BLOCKED approval_expired
  5. Otherwise set published = 1 only while the fingerprint still matches, and return MOCK_PUBLISHED

edit changes the text or destination and clears the fingerprint. reject clears it. approve stores a fingerprint only when the typed line is exactly APPROVE.

This is a local demonstration, not authenticated multi-user authorisation. Someone with access to the database or the Python process can change the local policy. In production, a separate service owns approvals, verifies the reviewer, enforces tenant access, and keeps an audit trail.

Why is approved=true supplied by the model insufficient? The model can say it. The approval has to be bound to the exact content, the destination, the reviewer action, and a lifetime, and checked by code the model cannot call.

This is a design check. The Python registry does not create managed Cloud resources.

Local control

Managed-platform responsibility

REGISTRY records the owner and permitted tools

Register approved agents and endpoints with identity and ownership

Tool allowlist in the plugin

Access policy for the authenticated calling principal

Mock publish

A separately protected action endpoint

Callback enforcement

Application control, plus a gateway path that traffic cannot skip

Local trace

Centralised audit and operational telemetry

For a managed exercise, use Google's Agent Gateway codelab after its project, identity, and network setup. Verify all of the following:

  • An approved destination is registered, with an owning team
  • The calling agent is identified by authenticated identity, not by a name the model supplied
  • Relevant traffic is routed through the selected gateway mode
  • An authorised request succeeds
  • An unauthorised principal, or a forbidden destination, fails
  • The deployment cannot reach that destination through an ungoverned path

Registering an endpoint does not protect traffic. The policy and the enforced route provide the boundary. Human approval for the exact content remains an application responsibility.
